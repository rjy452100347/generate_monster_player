## 3. 类别与标注约定

| YOLO 类别 ID | 名称 | 范围 |
| --- | --- | --- |
| `0` | `monster` | 活体怪物；站立、移动、受击、攻击、技能、跳跃、飞行动作 |
| `1` | `player` | 合成的玩家角色整体；不区分主控角色和其他玩家 |

NPC、宠物、技能特效、伤害数字、掉落物、金币和怪物死亡动画均不属于这两个目标类。玩家虽由 `distractors.py` 构造，但在 `label_players: true` 时会标为 `player`。

`box_quotas` 统计**每图怪物数**，`player_quotas` 统计每图人物数。`negative_*` 或 `positive: false` 表示没有活体怪物，仍可能有人物标签，例如 `negative_actor`。只有两类目标都不存在时，YOLO 标签文件才为空。

所有输出图片固定为 **宽 1280 × 高 224**，JPEG 质量 88、关闭色度子采样。综合生成器会拒绝其他分辨率。

YOLO 每行格式为：

```text
class_id center_x center_y width height
```

坐标归一化到 `[0, 1]`；Manifest 和 COCO 的 `bbox` 使用像素单位 `[x, y, width, height]`。COCO 类别 ID 是 `1: monster`、`2: player`，比 YOLO ID 大 1。

框取精灵非透明区域的外接矩形，并裁切到画面范围；不是分割标注，也不是仅对遮挡后可见像素重新求框。宽、高至少为 4 像素。综合入口默认要求保留原精灵至少 30% 的非透明像素；60K 怪物默认可见比例下限为 15%，48K 配置提高到 30%；人物可见比例下限在渲染器中固定为 30%。怪物可见比例主要计算前景和覆盖物遮挡，没有完整计入怪物相互遮挡，应人工抽查密集重叠样本。

地图按 ID 分 train／val／test，现有两套数据均为 141／18／18 张地图，而且两套数据的地图拆分一致。单地图独有怪物对应地图会保留在 train。新客户端或新地图范围生成的集合，仍需重新核对拆分。


### 5.5 生成参数速查

| 参数 | 含义 |
| --- | --- |
| `--config` | 必填，YAML 配置路径 |
| `--limit` | 小样本总数；建议使用正整数；不传则按完整配额 |
| `--name` | 覆盖输出子目录名；不会修改配置文件 |

校验入口只接受 `--config` 和 `--dataset`，样本总数从该目录的 `generation_plan.json` 读取，没有 `--limit`。

## 6. 续传、复现与故障处理

同一份代码、配置、客户端资源和参数下，重复执行相同生成命令可继续未完成样本。生成器会检查 seed、总数、调度哈希和配置哈希；Manifest 记录已完成样本，图片／标签先写临时文件再分别替换，Manifest 每条执行刷新和落盘。

续传遇到 Manifest 指向的图片或标签缺失，会剔除对应记录并重新生成。文件“存在但损坏”不会自动修复；Manifest JSON 行损坏也没有通用修复逻辑。已生成满额但覆盖率不合格时，重跑同一命令通常只跳过旧样本，不会自动补足覆盖。

| 现象 | 检查和处理 |
| --- | --- |
| `existing output uses a different generation plan` | 使用新 `--name`；不要删除旧计划来强行续传 |
| `free disk space below configured safety threshold` | 释放输出所在盘空间，再执行相同命令；保留输出和缓存 |
| `could not generate ... after configured attempts` | 查看输出目录 `failures.jsonl` 中目标数量、拒绝原因、地图和最后异常 |
| 校验退出码 1 | 查看 `validation_report.json.errors`；生成成功不代表校验成功 |
| 资源找不到、地图数量不足 | 检查客户端版本、资源目录、`map_range` 和索引缓存；旧资源引用失效时索引会尝试重建 |
| 人物不能合成或人物配额反复失败 | 检查 Character 图集、对应动作与部件锚点，抽查检查图 |
| 首次运行长时间没有生成进度 | 可能仍在索引、解压或地图几何预处理；结合 CPU、磁盘与日志判断 |

不要让多个进程同时写同一输出目录。原脚本没有自动日志重定向；项目 `logs` 目录中存在历史日志，并不代表每次运行都会自动产生日志。

## 7. 关键配置说明

| 配置 | 60K 当前值／含义 |
| --- | --- |
| `seed` | 83，采样种子；不能单独保证跨代码／客户端版本复现 |
| `label_players` / `class_names` | `true` / `[monster, player]`；顺序决定类别 ID |
| `image` | `{width: 1280, height: 224}`，综合流程固定 |
| `splits` | `{train: 48000, val: 6000, test: 6000}` |
| `map_range` | `[100000000, 199999999]`；进一步过滤正常、有怪、有平台的地图 |
| `box_quotas` | 每图 0–20 个怪物的图片配额，合计 60,000 |
| `player_quotas` | 每图 0–5 个人物的图片配额，合计 60,000 |
| `scenarios` | 稀疏、常规、多平台、密集、裁切、前景遮挡、大小极值、低频动作、飞跳及无怪物场景 |
| `action_weights` | 站立／移动／攻击／受击／技能／跳跃／飞行的采样权重，不是最终精确动作配额 |
| `minimum_mob_boxes` | 每种怪物至少 1,000 框，完整集验收条件 |
| `minimum_frame_uses` / `minimum_death_frame_uses` | 活体动作帧至少 50 次／死亡帧至少 20 次 |
| `minimum_player_boxes` | 人物总框数至少 49,500 |
| `visual_checks` | 500，按场景向上取整分配，所以现有检查图为 510 张 |
| `resource_cache` / `map_cache` | 384／32，缓存数量参数，不是 MB |
| `max_attempts` | 每个样本最多 240 次尝试；48K 为 300 |
| `minimum_free_gb` | 输出盘剩余空间阈值，5 GB |

调整规模时优先使用 `--limit` 做试验。正式修改配置时，应让怪物数、人物数、场景数和 split 配额合计一致，并保证场景的 `positive`、`min/max_instances`、`min/max_players` 能容纳这些配额。`minimum_*` 多为验收目标，不保证生成器一定满足。

## 8. Python 与外部程序调用

### 8.1 只创建计划，不加载客户端

在项目根目录执行下面的 Python 代码，可先检查拆分和框数预算；不会生成图片或写数据目录。

```python

from pathlib import Path
import yaml
from classic_dataset.comprehensive import build_schedule

config = yaml.safe_load(
    Path("configs/comprehensive_60k_2class.yml").read_text(encoding="utf-8")
)
schedule = build_schedule(config, limit=120)
print(Counter(sample.split for sample in schedule))
print("怪物框预算:", sum(sample.target_count for sample in schedule))
print("人物框预算:", sum(sample.player_count for sample in schedule))
```

### 8.2 同进程调用生成和校验

```python
from pathlib import Path
from classic_dataset.comprehensive import generate
from classic_dataset.validate_comprehensive import validate

config = Path("configs/comprehensive_60k_2class.yml")
output = generate(
    config_path=config,
    limit=120,
    name="comprehensive_api_smoke_20260920",
    overwrite=False,
)
report = validate(config_path=config, dataset=output)
if not report["ok"]:
    raise RuntimeError(report["errors"])
print(output / "data.yaml")
```

函数签名：

```python
generate(config_path: str | Path, limit: int | None = None,
         name: str | None = None, overwrite: bool = False) -> Path
validate(config_path: str | Path, dataset: str | Path) -> dict
```

`generate()` 失败会抛异常；`validate()` 的常规校验不通过会返回 `ok=False`，调用方需检查，严重文件／解析问题也可能直接抛异常。CLI 校验入口会将 `ok=False` 转成退出码 1。

## 10. 48K 扩展与稀有怪物补丁

`configs/hard_negative_48k_2class.yml` 使用同一综合生成器，重点增加掉落物、宠物和战斗干扰。仍只有 monster／player 两类，48,000 张中 22,000 张无怪物；每图 0–3 个人物，40,000 张带计划内掉落物。物品去重后配置要求 7,296 种视觉外观，最低使用次数 train／val／test 为 12／4／4；保留的挑战物品不进入 train。

先生成 1,000 张小样本，当前计划为 800／100／100：

```powershell
& .\.venv\Scripts\python.exe -u -m classic_dataset.comprehensive `
  --config configs\hard_negative_48k_2class.yml `
  --limit 1000 --name hard_negative_pilot_20260920
if ($LASTEXITCODE -ne 0) { throw '48K 小样本生成失败' }

& .\.venv\Scripts\python.exe -u -m classic_dataset.validate_comprehensive `
  --config configs\hard_negative_48k_2class.yml `
  --dataset 'N:\Program Files\map\hard_negative_pilot_20260920'
if ($LASTEXITCODE -ne 0) { throw '48K 小样本校验失败' }
```

新正式扩展集应去掉 `--limit` 并使用新名称；若要续传旧 48K，应先确认仍使用相同客户端素材。`item_index_source` 与 `map_geometry_source` 当前指向旧扩展集中的共享索引；素材更新时需审查其适用性。几何共享文件不存在时，生成器可能将新计算结果写回共享路径。

| 训练配置（位于旧 48K 目录） | 组成 | train / val / test |
| --- | --- | --- |
| `data.yaml` | 仅 48K | 38,400 / 4,800 / 4,800 |
| `data_combined_60k_plus_hard_negative.yaml` | 60K + 48K | 86,400 / 10,800 / 10,800 |
| `data_combined_60k_hard_negative_balance.yaml` | 60K + 48K + 97 张补丁 | 86,497 / 10,800 / 10,800 |

联合配置同时合并两套数据的 train、val、test，并非固定沿用原 60K 的 val／test。修改客户端、seed 或地图范围后，联合训练前应重新检查跨集合地图泄漏和图片重复；生成器的单集去重不等于联合去重。

补丁入口：

```powershell
& .\.venv\Scripts\python.exe -u -m classic_dataset.balance_patch `
  --config configs\hard_negative_48k_2class.yml
```

这是会写文件的操作：读取配置默认 48K 目录，输出固定子目录 `rare_mob_balance_patch`，并更新 48K 目录中的联合 YAML 和 `combined_validation_report.json`。它没有 `--name`，也不会自动跟随此前 CLI 的 `--name`。若为新扩展集生成补丁，应复制配置并把 `name`、`output_root`、`base_dataset` 设为对应新数据，避免引用旧目录。

补丁用于调整怪物数量比例，不是所有覆盖问题的通用修复器；也不适合直接用 60K／48K 配额校验器验证，因为补丁采用独立计划和输出报告。

## 11. 验收范围与后续使用

正式校验涵盖 Manifest 总数／拆分／场景和框数配额、地图隔离、图片存在和 JPEG 尺寸、SHA256、精确重复、pHash 近似重复比例低于 0.5%、YOLO 行格式和坐标范围、框尺寸、活体／死亡动作区分、平台误差、检查图和导出文件存在性；启用相关场景时还检查布局、掉落物数量和物品覆盖。

完整规模下额外读取客户端检查怪物、活体动作帧、死亡帧和人物覆盖，以及常见／稀有怪物框数比。当前代码排除了不能形成至少 4×4 框的活体占位帧，但历史报告可能生成于旧代码，不能据此直接宣布历史错误消失。

该校验器未逐行反算 YOLO 坐标与 Manifest 框完全一致，也没有完整解析核对 COCO 内容；数量统计不代替视觉验收，合成数据验收也不代表真实游戏截图上的识别效果。训练前应处理报告错误并抽查检查图；训练效果应另用符合实际截图区域和类别规则的真实图像评估。

本次已核对：环境可启动、CLI 参数、完整及小样本调度可建立、两个数据目录的图片／标签数量、旧计划兼容性、地图拆分一致性和已有补丁数量。未执行全量再生成、全量再校验或模型训练。
